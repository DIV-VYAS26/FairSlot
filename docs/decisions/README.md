# Architecture decision records

Use a short ADR for a significant architectural choice with meaningful alternatives
or long-term consequences. Do not create records for routine edits or unresolved ideas.

When needed, use 0001-short-title.md and include: date, status (proposed/accepted/
superseded), context, decision, alternatives and consequences. Link a replacement
when superseding an accepted decision; preserve the reasoning history.

No ADRs have been created in Phase 0. Open questions remain in architecture.md and
progress.md until discussed. Accepted records must agree with the architecture and
implementation; update related documentation when a decision is approved.
